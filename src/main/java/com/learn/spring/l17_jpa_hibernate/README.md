# Lesson 17: JPA and Hibernate (ORM)

**ORM** (Object-Relational Mapping) lets you work with Java objects while Hibernate writes the SQL.
**JPA** (`jakarta.persistence`) is the standard API and **Hibernate** is the most common implementation.
Spring wires them together and adds transactions. The demo logs every SQL statement, so read the output.

## Mapping
| Annotation | Meaning |
|---|---|
| `@Entity`, `@Table` | class to table |
| `@Id`, `@GeneratedValue` | primary key, generated by the database |
| `@Column(nullable, length, unique)` | column details |
| `@Enumerated(EnumType.STRING)` | store enums by name (never ORDINAL) |
| `@Embeddable` / `@Embedded` | value object stored in the owner's table |
| `@OneToMany(mappedBy)` / `@ManyToOne` | one author has many books; the many side owns the foreign key |
| `@ManyToMany` + `@JoinTable` | books and tags through a join table |
| `cascade`, `orphanRemoval` | propagate persist/remove to children |
| `@Version` | optimistic locking |

## The persistence context (the most important idea)
- The `EntityManager` tracks every **managed** entity it loads or persists in the current transaction.
- **Entity states**: new (transient), **managed**, **detached** (after the transaction ends), removed.
- **Dirty checking**: change a managed entity's field and Hibernate issues the UPDATE at commit. No `save()` needed.
- **First-level cache**: `find` twice with the same id gives the same object and one SELECT.
- `merge()` copies a detached object back into a managed one.

## Fetching
- `@OneToMany`/`@ManyToMany` are LAZY by default. `@ManyToOne`/`@OneToOne` are EAGER by default, so make them LAZY.
- **LazyInitializationException**: a lazy association accessed after the transaction is over.
- **N+1 problem**: 1 query for the list plus 1 per row for the association. Fix it with `JOIN FETCH`, an entity graph, or batch fetching.
  The demo counts the statements.

## Queries
JPQL (`SELECT b FROM Book b WHERE b.author.name = :name`), DTO projections (`SELECT new ...`), native SQL.

## Production notes
- Use migrations (Flyway/Liquibase) instead of `hbm2ddl.auto`.
- Always look at the generated SQL during development.
